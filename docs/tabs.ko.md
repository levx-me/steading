# 탭

[English](tabs.md) · **한국어** · [← README](../README.ko.md)

모든 탭은 같은 방식으로 동작합니다. 위에는 실행 목록이 최신순으로(최근 20개, git은 50개), 아래에는 고른
실행의 출력이 나옵니다. 탭 이름 옆에는 최근 상태가 붙습니다. `✓` `✗`, 실행 중이면 스피너, 떠 있는 서버는
`●`입니다. 다른 탭에 새 실행이 들어오면 그 탭이 빨갛게 바뀌고, 그 탭을 열 때까지 그대로입니다. 탭 줄 오른쪽 끝에는 그런 탭의 수(`2 new`)가 나오고, 화면 밖으로 밀린 쪽에 있으면 그쪽 화살표도 빨개집니다. 숫자나 그 화살표를 누르면 가장 가까운 새 탭으로 갑니다(보던 탭은 그대로). 새 줄은 탭 색으로 시작해 서서히 돌아옵니다.

실행 기록은 문장으로 표시됩니다. 테스트는 무엇을 테스트하는지("Testing auth", "Running all the tests"), 빌드는
무엇을 빌드하는지("Building for release"), 배포는 어디로 가는지("Deploying to production"), jobs는 에이전트가 쓴
설명이나 명령의 주된 단계("Running s3.py", "Waiting 60s")로 보여 줍니다. 명령 자체는 실행 상자 맨 위에 나옵니다.

## agents

**보여 주는 것**: 맨 위에 에이전트 자신, 그 아래에 지금 일하는 Claude Code 서브 에이전트(백그라운드와
워크플로 에이전트 포함, 서브 에이전트가 띄운 서브 에이전트는 그 아래에 들여 써서). 에이전트마다 두 줄입니다.

```
⠼ add refresh tokens to the auth middleware    opus-5-5
    Bash npm test                         ▰▰▰▱▱ 3/5  2m 16s
⠼ Map the auth tests                            haiku-5-5
    Read src/auth/refresh.test.ts                      40s
```

첫 줄은 이름과 모델, 둘째 줄은 지금 하는 일(서브 에이전트는 실행 중인 도구, 없으면 마지막으로 한 말. 메인 에이전트는 진행 중인 할 일, 없으면 내가 마지막으로 한 요청. 또는
`waiting for you`), 할 일 진행(할 일 목록이 있을 때), 일한 시간입니다. [wanjang](https://github.com/levx-me/wanjang) 플러그인이 있으면 일하는(또는 자기 일을 기다리는) 서브 에이전트는 일한 시간 대신, 끝날 법한 시각까지 차오르는 막대와 1초마다 줄어드는 카운트다운(mm:ss)을 보여 줍니다. 그 시각을 넘기면 막대가 호박색으로 바뀌고 늦어도 끝날 시각까지 세며, 그마저 넘기면 `+mm:ss`로 넘긴 시간을 셉니다. 목록 위 테두리에는 전부 끝날 시각이 나옵니다(`~16:20 · 11:42 left`). deck은 이 탭이 보일 때만 wanjang의 `status --eta`를 30초에 한 번까지 묻고 나머지는 직접 셉니다. 좁은 deck에서는 막대를 빼고 카운트다운만 남깁니다. wanjang이 없으면 달라지는 것이 없습니다. 하나를 고르면 전체가 카드로 나뉘어 보입니다(**activity** 카드: 에이전트가 한 일을 최신순 문장으로. 기본 5개, "▾ more"로 전부(카드 안에서 스크롤). 오래 걸린 명령에는 출력으로 가는 "↗ jobs #n"). 상태와 분당 토큰 수, 잘리지 않은 세션 제목(서브 에이전트는 맡은 작업),
모델과 effort, 컨텍스트 사용량, 토큰, 종류별 도구 사용, 할 일 목록입니다. **team** 카드에는 그 에이전트가 띄운 하위 에이전트 중 아직 있는 것(일하는 중이거나 다음 메시지를 기다리는 팀원, 모델과 시간)가 나오고, 목록에서는 하위 에이전트의 하위 에이전트가 가지선(├ └)으로 이어집니다. 할 일에서 enter를 누르면 그 할 일이 나온 대화가 시간순으로 보입니다.

**나타나는 때**: 패널에서 세션이 시작될 때, 그리고 에이전트가 서브 에이전트에게 일을 맡길 때.
서브 에이전트가 일하는 중인지는 Claude Code의 SubagentStart/SubagentStop 훅(사이드바의 `$crew`도 읽는 같은 기록)으로 정하므로, 몇 분 동안 말없이 생각하는 에이전트도 목록에 남고 대기 중인 팀원은 빠집니다. 나머지는
[zoetrope](https://github.com/furkankly/zoetrope)처럼 세션의 대화 기록 파일에서 읽습니다.

**기다리는 중.** 자기 턴은 끝났지만(끝났거나, 팀원이 대기로 들어감) 스스로 시작한 일이 아직 남은 서브 에이전트는
`◷`로 흐리게 목록에 남고, 무엇을 기다리는지 한 줄로 보여 줍니다: `waits on 1 background command · 2 teammates`.
남은 일이란 백그라운드로 돌린 명령(시간 초과로 백그라운드로 넘어간 것 포함) 가운데 대화 기록에 task-notification도,
출력 파일에 종료 줄도 아직 없는 것, 그리고 그 에이전트가 띄운 하위 에이전트 중 아직 있는 것(일하는 중, 자신도 기다리는 중, 대기 중인 팀원.
대기 중인 팀원도 메시지를 받을 수 있으니 셉니다)입니다. 기다릴 것이 하나도 남지 않거나, 보고를 넘겨 실행이 완전히 끝나면 목록에서 빠집니다. 세션 프로세스가
다시 시작되기 전이나 3시간보다 오래전에 시작한 백그라운드 명령은 끝난 것으로 봅니다. 기다리는 것은 일이 아니므로 사이드바의
`$crew`는 세지 않고, team 카드에는 `◷`로 나옵니다.

## files

**보여 주는 것**: 이 세션의 에이전트(메인과 서브에이전트)가 읽거나 쓴 파일을 저장소 루트 기준의 폴더 트리로
보여 줍니다. 저장소 밖의 파일은 자기 폴더 아래에 나옵니다. 폴더가 먼저 나오고, 폴더가 하나씩만 이어지면 한
행으로 합치며, 최근 파일 500개까지 보여 줍니다.

```
▾ src
  ▾ auth
    ✎ refresh.ts     ⠋ builder  +12 -3   4s
    ◦ session.ts     ✓ scout              1m
```

한 행은 쓴 파일이면 `✎`, 읽기만 했으면 `◦`(흐리게), 파일을 쓴 에이전트가 지금 일하는 중이면 `⠋`, 끝났으면
`✓`, 마지막으로 손댄 에이전트(`builder`, `scout`, `main`), git 변경량, 마지막으로 손댄 뒤 지난 시간으로
이루어집니다. 변경량은 `git diff --numstat HEAD`의 `+N -M`이고, git이 모르는 파일은 `+N new`, 지워진 파일은
`deleted`, 바이너리는 `binary`로 나옵니다. `enter`(또는 `l`)는 그 파일의 diff를 로그 화면에 보여 주고(`esc`,
`q`, 백스페이스로 나옴), `o`는 deck 아래에 herdr 분할 창을 열어 `$EDITOR`(없으면 `vi`)로 파일을 엽니다(herdr 밖에서는
안내만 나옴). `y`는 경로를 복사합니다. 폴더 행에서 `enter`(또는 `l`)는 폴더를 접거나 펼칩니다(`▸` 접힘, `▾` 펼침).
deck이 좁으면 시간이 먼저, 그다음 에이전트, 그다음 git 변경량이 사라지고, 이름은 최소 12칸쯤 남기며 편집 상태(`⠋`, `✓`)는
그대로 남습니다. 파일이 없으면 하단 키 안내에서 `enter`, `o`, `y`가 빠지고, 잠깐 나오는 메시지("herdr did not open a pane" 등)는
탭을 떠나거나 다시 돌아오면 사라집니다.

**들어오는 때**: 에이전트의 Read, Edit, Write, NotebookEdit 호출이 끝났을 때입니다. sidebar 훅이 세션의
`<sid>.files` 기록에 추가합니다. 파일 시스템을 감시하지 않습니다. git은 탭이 보이는 동안에만, 1초에 한 번까지만 실행합니다.

## jobs

**보여 주는 것**: 테스트도 빌드도 아니면서 오래 걸리는 명령들. 대기 루프, 설치, timeout을 길게 준
스크립트 같은 것들입니다. 무엇을 하려는지(호출 설명), timeout 대비 얼마나 돌았는지(`15s of 2m`),
나오는 대로의 출력을 보여 줍니다. 끝나면 출력과 종료 코드를 남기고, 실패는 빨간색으로 표시합니다.

**나타나는 때**: 그 밖의 명령이 10초를 넘겼을 때(설정 `,`의 jobs 기준 시간: 5·10·30초). 더 짧은 명령은 나타나지 않습니다. 출력은 Claude Code가
그 호출의 출력을 쓰는 파일에서 읽으므로 호출 자체는 바꾸지 않습니다.

## servers

**보여 주는 것**: 이 프로젝트를 위해 떠 있는 개발 서버와 각 서버의 포트, 로그(서버가 쓰는 파일이나 서버가
출력하는 herdr 패널). 로그는 맨 아래를 따라가고, 스크롤하면 `esc`를 누를 때까지 멈춰 있습니다. `o`로
브라우저에서 엽니다.

**나타나는 때**: 프로젝트 안의 프로세스, 또는 같은 herdr 워크스페이스의 패널에서 시작된 프로세스가 포트를
열 때. `npm run dev`, `next dev`, `vite`, `anvil`, `uvicorn`, `flask run`, … 명령은 그대로 두고 탭에
새로움 표시만 붙입니다.

## build · test

**보여 주는 것**: 실행마다 셸에서 보던 색 그대로의 실시간 출력. 상자 맨 위에는 상태 배지(`✓ PASSED`, `✗ FAILED`,
`⠼ RUNNING`)와 실행 위치·걸린 시간·끝난 시각이, 테스트는 실행기의 요약에서 읽은 통과·실패 수 막대가 나오고,
로그 왼쪽에는 줄 번호와 함께 오류 줄은 빨간 막대, 경고 줄은 노란 막대가 붙습니다. jobs와 deploy도 같은 모양입니다.

**나타나는 때**: 에이전트가 실행할 때.

- 테스트: `npm/pnpm/yarn test[:x]`, `vitest`, `jest`, `pytest`, `go test`, `cargo test`, `bun test`,
  `deno test`, `forge test`, `make`/`just test`, `./test.sh` 같은 스크립트
- 빌드: `npm/pnpm/yarn run build[:x]`, `tsc`, `next build`, `vite build`, `go build`,
  `cargo build`/`check`, `forge build`, `make`/`just build`, `./build.sh` 같은 스크립트

단순한 호출(`[cd DIR &&] [VAR=val] [time|timeout N|env] [npx|pnpm|…] RUNNER [args]`, 여기에 `2>&1`과
`| tail/head -n N` 하나까지)은 deck 안에서 실행되고, 에이전트는 여전히 일반 텍스트와 실제 종료 코드를
받습니다. 체인이나 파이프 안에 있으면(`git status; npm test | grep FAIL`) 쓴 그대로 실행되고, 끝난 뒤
나타납니다.

## git

**보여 주는 것**: 저장소를 바꾼 명령 전부. 단계마다 한 줄(`git add · git commit "Fix it" · git push`),
실행된 브랜치, 남긴 커밋을 보여 주고, 커밋은 메시지 전체를 보여 줍니다. 목록 테두리에는 지금의 저장소
상태가 나옵니다.

```
╭─ runs · 12 ─────────────── main ↑2 · 3 changed ─╮
```

브랜치, 푸시하지 않은 커밋(`↑`)과 받지 않은 커밋(`↓`), 커밋하지 않은 파일 수(없으면 `clean`)입니다.

**나타나는 때**: `git`이 들어 있는 명령이 실행되어 무언가를 바꿨을 때. `git status`, `git log` 같은 조회는
제외합니다.

## deploy

**보여 주는 것**: 배포마다 출력과 종료 코드.

**나타나는 때**: 실제 배포가 실행됐을 때. `vercel`, `railway up`, `netlify deploy`, `fly deploy`,
`wrangler deploy`, `firebase deploy`, `gcloud run deploy`, `terraform apply`, `kubectl apply`,
`helm upgrade`, `forge script --broadcast` 등([전체 목록](../bin/classify)). `vercel ls`, `fly status`
같은 조회는 제외합니다.

## system

**보여 주는 것**: 이 컴퓨터. 전체 CPU와 코어마다 작은 막대, 부하 평균, 전체 중 사용 중인 메모리,
Mac에서 [macmon](https://github.com/vladkens/macmon)이 있으면 GPU, 전력, CPU·GPU 온도. 그 아래
btop처럼 모든 프로세스(Pid, Program, Command, User, MemB, Cpu%)를 CPU를 많이 쓰는 순으로 보여
줍니다. 선택한 행은 `j` `k`로 옮깁니다. btop처럼 행을 고르는 것이라, 다시 정렬되면 그 행에 온 프로세스가
선택되고, 목록은 키와 휠로만 스크롤됩니다. 예외는 하나입니다. `enter`로 펼친 세션은 다시 접거나 커서를
옮기거나 세션이 끝날 때까지 커서가 따라가고, 스크롤은 그 세션과 그 아래 행이 보이게 움직입니다. `s`는 메모리
순으로, `u`는 내 프로세스만 보여 줍니다. Claude 세션은 agents 탭 색의 한 행으로, 명령 앞에 작업 중인
폴더 이름을 붙이고 그 아래 프로세스(MCP 서버, node, 셸)의 CPU와 메모리를 합쳐 보여 주며, `enter`로
펼칩니다. 프로젝트의 개발 서버는 세션에 넣지 않고, 서버와 그 아래 프로세스를 초록색 별도 행에 포트와 함께
보여 줍니다. `K` 다음 `y`로 `K`를 누른 때 선택돼 있던 프로세스를
끝냅니다(SIGTERM. 세션이면 claude 프로세스만). 그 pid가 여전히 같은 프로세스일 때만입니다. deck에서 무언가를 바꾸는 유일한 동작입니다. 탭이
보이는 동안에만 2초마다 측정하고(이 탭을 띄운 deck이 여럿이어도 한 곳에서만 측정), 이 탭에는 새 항목
표시가 붙지 않습니다.

**여는 것**: `o`(또는 버튼 클릭)로 herdr의 `system` 워크스페이스로 갑니다. 처음에는 만들면서 `btop`을
넓게, Mac에서 macmon이 있으면 옆에 `macmon`을 좁게 엽니다. 그 뒤로는 어느 deck에서든 그 워크스페이스로
갑니다. 도구가 없으면 설치 방법을 보여 줍니다. macOS는 `brew install btop macmon`, Linux는 배포판
패키지 관리자로 `btop`.
